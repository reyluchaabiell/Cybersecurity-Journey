Kesimpulan:
Challenge phishing ini nunjukin pola email jebakan yang umum: subject disusun rapi dengan nomor transfer, pengirim yang terlihat sah, dan lampiran terkompresi yang menyembunyikan tipe file asli (.CAB di nama tapi sebenarnya RAR). Pelajaran penting:

- Selalu periksa header pesan (From:, Reply-To:, Received:) dan source mentah (Ctrl+U) untuk melacak IP asal dan jalur pengiriman.
- Cek record DNS (SPF/DMARC) pada domain pengirim untuk menilai apakah domain itu terkonfigurasi dengan benar atau kemungkinan dipalsukan.
- Jangan percaya cuma nama file — simpan dan periksa hash/metadata lampiran di lingkungan yang terisolasi, gunakan layanan seperti VirusTotal untuk informasi cepat (ukuran, tipe, deteksi).
- Kalau nama file klaim satu tipe tapi tipe sebenarnya beda → anggap mencurigakan. Ini tanda obfuscation untuk mengelabui pemeriksaan kasual.

Saran operasional cepat: analisis lampiran di VM terisolasi, ekstrak arsip dengan aman, dan periksa file yang diekstrak dengan tool statis sebelum menjalankan apa pun.
 
English Ver:
Intro:
First, open the challenge.eml file using Thunderbird (or any mail client that can read .eml).

Q1 — What is the Transfer Reference Number listed in the email's Subject?

How to find it: Inspect the .eml file and focus on the “Transfer Reference Number” area in the Subject line.
Answer: 09674321

Q2 — Who is the email from?

How to find it: Look at the From: header in the email.
Answer: Mr. James Jackson

Q3 — What is his email address?

How to find it: The sender’s email address is shown next to the name in the header.
Answer: info@mutawamarine.com

Q4 — What email address will receive a reply to this email?

How to find it: Check the email headers for the Reply-To: field.
Answer: info.mutawamarine@mail.com

Q5 — What is the Originating IP?

How to find it: Open the raw source of the .eml file (in Thunderbird press Ctrl+U) and look for Received: lines — the originating IP will be listed there.
Answer: 192.119.71.157

Q6 — Who is the owner of the Originating IP? (Do not include the "." in your answer.)

How to find it: Use a WHOIS/OSINT service (e.g., whois.com) and search the IP. Check the Organization field.
Answer: Hostwinds LLC

Q7 — What is the SPF record for the Return-Path domain?

How to find it: First identify the Return-Path domain in the .eml (here it’s mutawamarine.com), then query a DNS/SPF lookup tool (for example mxtoolbox.com).
Answer: v=spf1 include:spf.protection.outlook.com -all

Q8 — What is the DMARC record for the Return-Path domain?

How to find it: Use a DMARC lookup tool (for example, dmarcian.com) on the same domain and read the DMARC record.
Answer: v=DMARC1; p=quarantine; fo=1

Q9 — What is the name of the attachment?

How to find it: Scroll to the bottom of the .eml file where attachments are listed; the filename is shown there.
Answer: SWT_#09674321____PDF__.CAB

Q10 — What is the SHA256 hash of the file attachment?

How to find it: Save/download the attachment, then compute its SHA256 hash on the CLI:
sha256sum SWT_#09674321____PDF__.CAB
Answer: 2e91c533615a9bb8929ac4bb76707b2444597ce063d84a4b33525e25074fff3f

Q11 — What is the attachment’s file size? (Don't forget to add "KB" to your answer, NUM KB)

How to find it: Submit or look up the file or its hash on a service like VirusTotal to view basic properties including file size.
Answer: 400.26 KB

Q12 — What is the actual file extension of the attachment?

How to find it: Check the attachment’s basic properties (e.g., on VirusTotal) to see the real file type/extension.
Answer: RAR

Conclusion:
This phishing challenge shows a typical e-mail-based lure: a crafted subject with a transfer reference, a sender that looks legit, and a compressed attachment that hides its true type (.CAB named file that is actually a RAR). Key takeaways:

- Always inspect message headers (From:, Reply-To:, Received:) and raw source (Ctrl+U) to find origin IPs and delivery paths.
- Check DNS records (SPF/DMARC) for the sending domain to see whether the domain is properly configured or likely spoofed.
- Never trust file names alone — download and hash/inspect attachments in an isolated environment, and use services like VirusTotal for quick metadata (size, type, detection).
- When an attachment’s claimed type (filename) and actual type differ, treat it as suspicious — this is a classic sign of obfuscation used to bypass casual checks.

Quick operational advice: analyze attachments in an isolated VM, extract the archive safely, and inspect extracted files with static tools before executing anything.
